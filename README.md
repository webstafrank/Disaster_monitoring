# KSA Rangeland Intelligence Hub

On-prem disaster-monitoring platform for Kenya's Arid and Semi-Arid Lands (ASALs).
A WFP · KSA (Kenya Space Agency) joint initiative that turns Earth Observation data
into county-level decision support for drought and disaster response.

Pick a **location** (an ASAL county) and a **disaster indicator** (NDVI, VCI, SPI,
rainfall, flood). The platform pulls the indicator time-series, runs deterministic
analytics (severity, trend, anomaly), and generates a plain-language briefing grounded
in those numbers. Everything runs on one physical server.

## Two machine spaces

The insight is deliberately split so the model never invents figures:

- **Deterministic** (`services/api/app/analytics.py`) — severity class, trend, anomaly.
  Same series in, same numbers out. Fully unit-tested, no model, no network.
- **Latent** (`services/llm`) — the plain-language briefing, generated by local Claude
  Code from the deterministic numbers.

`services/api/app/insight.py` assembles both.

## Services

| Service | Dir | Port | Role |
|---|---|---|---|
| frontend | `app/` | 3000 | Next.js UI, calls the API via `app/lib/api.ts` |
| api | `services/api` | 8000 | Contract endpoints + deterministic analytics |
| llm | `services/llm` | 8100 | Shells to local Claude Code for insight text |
| geoserver | (image) | 8080 | Serves EO map layers (WMS/WFS) |
| db | (image) | 5432 | PostgreSQL + PostGIS |
| nginx | `deploy/` | 443 | TLS termination, single entry point |

Each service is an independent deploy unit with its own tests. See its README and
[`ARCHITECTURE.md`](ARCHITECTURE.md) for the full diagram.

## Contract

`contracts/openapi.yaml` is the single source of truth. `contracts/types.ts` mirrors it
for the frontend; `services/api/app/schemas.py` mirrors it for the backend. The
`services/api/tests/test_contract.py` gate test fails if the served schema drifts.

Endpoints: `GET /health`, `GET /locations`, `GET /indicators`, `GET /observations`,
`POST /insight`.

## Data source

Selected by `DATA_SOURCE`:

- `stub` (default) — deterministic placeholder series, tagged `source: "stub"` in every
  response so it is never mistaken for real data. Lets the whole loop run today.
- `postgis` — the real feed. `services/api/app/sources/postgis.py` reads per-county
  monthly values straight from PostGIS (schema in `services/api/sql/observations.sql`).
  GeoServer reads the same database for map layers but is not in the charts path.

The catalog of counties and indicators is shared across sources
(`services/api/app/sources/catalog.py`); only the values differ.

## Run locally

```bash
# backend (from repo root, using the local venv)
DATA_SOURCE=stub .venv-test/bin/python -m uvicorn app.main:app --app-dir services/api --port 8000
LLM_MODE=claude .venv-test/bin/python -m uvicorn app.main:app --app-dir services/llm --port 8100

# frontend
npm install
npm run dev   # http://localhost:3000, NEXT_PUBLIC_API_BASE defaults to /api
```

## Testing lanes

- **Gate** (free, deterministic, < 2s, every commit): `./scripts/gate.sh`. Enable the
  pre-commit hook with `git config core.hooksPath .githooks`.
- **Eval** (paid, periodic, before ship + nightly): `services/*/evals`. Runs real Claude
  Code and scores narrative quality against a threshold; skips cleanly when the model is
  unavailable.

## Deploy (server)

```bash
cp .env.example .env    # fill in secrets, never commit
git config core.hooksPath .githooks
./deploy.sh             # pull, build, up, health-check
```

Server prep: install Docker + Compose, provision TLS certs into `deploy/certs/`, and
authenticate the `claude` CLI for the llm service (host run or mounted config). See
`services/llm/README.md`.

## Tech

Next.js 16 (App Router, React 19), OpenLayers + Recharts for maps and charts, Tailwind 4
on the frontend; FastAPI + Python on the backend; PostgreSQL/PostGIS and GeoServer for
spatial data. Vanilla by default, no framework-of-the-month.
